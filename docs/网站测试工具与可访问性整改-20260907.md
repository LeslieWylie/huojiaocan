# 网站测试工具与活教参的采用方式

## 推荐组合

| 官方网站/工具 | 适用问题 | 活教参如何使用 |
|---|---|---|
| [PageSpeed Insights](https://pagespeed.web.dev/) | 加载性能、核心网页指标 | 检查公共入口与教材库；不能用首页分数代表登录后生成流程 |
| [WebPageTest](https://product.webpagetest.org/) | 不同网络/设备下的加载过程、请求瀑布 | 排查PDF慢、首屏资源阻塞；本轮未提交测试或购买服务 |
| [WAVE](https://wave.webaim.org/) | 直观看标签、结构和对比度问题 | 辅助人工检查；私人草稿和登录状态不提交第三方站点 |
| [axe + Playwright](https://playwright.dev/docs/accessibility-testing) | 自动检查表单名称、语义、对比度等 | 已接入本地开发依赖，不往教学模型注入测试工具 |
| [BrowserStack Live](https://www.browserstack.com/docs/live) | 真机浏览器兼容性 | 后续核对iPhone/Safari的PDF与课堂模式；本轮未购买或执行 |

不是工具越多越好：本轮先使用现有Playwright加axe形成可重复检查，性能工具与真机服务按遇到的问题再启用。未获得实测分数的工具，不写成已测通过。

## 学到并落实的测试原则

- 等待真实控件、加载状态和有限入场动画结束后检查。动画中途的透明度可能造成对比度误报，不能按错误采样结果大改主题色。
- 自动测试不等于完整可访问性认证。保留axe的`incomplete`人工待核对项，继续人工验证键盘、200%缩放和原始PDF内容。
- 不关闭对比度规则来获得绿色结果。真实违规必须修复，或明确记录未解决并保持失败状态。
- 不把公共空页面通过当作三卡内容、锁定态、弹窗与错误恢复均通过。

上述策略参考 [Playwright可访问性指南](https://playwright.dev/docs/accessibility-testing) 和 [web.dev人工测试指南](https://web.dev/learn/accessibility/test-manual)。

## 可重复命令

```bash
cd demo
# 本地构建和隔离测试服务
npx playwright test -c playwright.a11y.config.cjs
# 线上公共页面，只读且不登录
E2E_TARGET=production npx playwright test -c playwright.a11y.config.cjs
```

当前扫描范围：首页、教材库、登录页、匿名问答页；规则为WCAG A/AA相关自动化规则。输出保存到 `demo/node_modules/.cache/accessibility-results`，含命中元素及需要人工判断的项目。任何失败如实返回非零退出码，不修改生产数据。

## 本轮实际修改

- 引入仅开发环境使用的 `@axe-core/playwright`，不增加教师端运行时依赖。
- 调整公共入口的次要文字、金色说明、蓝色教材标签、登录提示及状态文字颜色；保留原绿色纸张风格。
- 发现目录辅助文字被旧CSS覆盖为7px；修正选择器优先级并提高到12px，使物理页说明可读。
- 首页金色标题按语义分组换行，避免末尾单字独占一行。
- 新增独立 `npm run test:a11y`，报告保留违规和人工待确认项。第一次实测也发现等待条件误选隐藏移动端控件，已修正测试，未把该失败冒充产品问题。

线上基线：稳定入场后四个公共页面均发现文字对比度不足。后续修复仅在开发分支，尚未发布；不能称线上这些问题已解决。

## 验证结果与限制

- 单测692/692通过，静态检查与生产构建通过。
- 可访问性场景8/8通过：4个公共页面 × 1280px/390px，自动规则无违规；仍保留人工待确认项，不称为WCAG认证。
- 已查看本地渲染截图，首页金色标题按“把一节课 / 完整带到课后”断行，不拆开“完整”。
- 没有测试私人草稿、登录后的三卡和PDF插件内部原文；PageSpeed/WebPageTest/BrowserStack只完成资料筛选，未获得其性能或真机测试结果。
- 本批在开发分支，未部署；线上基线问题仍需发布后复测。
- 布局与主导航浏览器回归5/5通过，其中31个声明页面分别在桌面/移动端检查渲染、溢出及基础控件，另覆盖主入口和教材导航。此结果不代表逐一执行所有业务按钮。
