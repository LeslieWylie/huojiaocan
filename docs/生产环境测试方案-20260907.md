# 活教参生产测试与下一步产品迭代

## 采用方案

采用现有 Playwright 做分层测试，不引入另一套自动化平台。发布先经过预览环境，再做固定域名只读巡检；真实写入与付费生成必须独立执行，不能混入常规冒烟。

依据：Playwright 官方建议隔离浏览器上下文；修改服务端状态的并行测试使用不同账号，登录状态文件不得入库。[认证与账号隔离](https://playwright.dev/docs/auth)
Vercel 的 Deployment Checks 可阻止未通过检查的部署提升为生产；是否启用需核实项目配置，本项目本轮没有擅自开启。[部署检查](https://vercel.com/docs/deployment-checks)

## 四层执行范围

| 层级 | 执行内容 | 数据与费用 | 发布判定 |
|---|---|---|---|
| 本地确定性回归 | 登录交接、失败恢复、版本冲突、锁定、按钮跳转 | 模拟账号和模型 | 必须通过；不能证明真实教学质量 |
| 公网只读冒烟 | 首页、公开目录、三篇课文搜索、PDF定位参数、引用往返、390px布局 | 不登录、不创建草稿、不调用生成接口；搜索会使用线上服务 | 必须通过；HTTP 200不够 |
| 预览受控写入 | 两个专用账号登录、创建/修改/锁定/恢复测试草稿、交叉访问拒绝、私人测试PDF | 独立测试账号与唯一运行前缀，单worker、无自动重试 | 测试数据不得进入正式教师账号；清理失败视为失败 |
| 真实模型质量对照 | 同模型同材料下12例基线与技能版对照 | 显式付费开关；每例固定调用上限，串行执行 | 引用造假、身份漂移、手改丢失、主流程阻断均禁止发布 |

## 受控写入设计（待实现与实测）

1. 使用两名已完成邮箱验证的专用测试账号；不能复用教师日常账号，不关闭生产邮箱验证。
2. 凭据通过环境注入，不写代码、登录截图、trace、HAR或报告。每个账号一个全新浏览器上下文，测试结束销毁。
3. 显式启用 `RUN_PRODUCTION_WRITES=true`，校验准确目标origin；没有开关或缺少账号则明确未执行，不算通过。
4. 每次创建使用 `hjc-e2e-<运行UUID>` 标题前缀。拿到ID立即记录本次创建清单；不得按模糊前缀扫描删除历史数据。
5. A创建无敏感内容草稿/PDF，B经真实API和页面尝试访问；对比返回码与内容不可见，不能仅靠隐藏按钮判断隔离。
6. 保存时检查返回版本，再刷新页面检查真实持久化；制造版本冲突只能修改本次测试草稿。
7. `finally` 仅按清单中的ID清理，并复核对象属于测试账号且标记匹配。结果未知时先查清单对象，不能再次生成或再次创建。
8. 真实生成不使用自动重试，记录同一请求与草稿；费用由调用上限控制，除非网关提供可靠账单，不能虚报人民币成本。

现有39项数据库RLS检查保留；它们不替代这一层。目前本轮未创建生产测试账号、未写入真实私人PDF，也未完成真实模型对照。

## 发布与回退

- 分支预览：先验证新功能、模型技能包是否可加载及受控写入。
- 生产：验收通过后再合并发布；`TEACHING_SKILLS_ENABLED`保持默认关闭直到质量对照通过。
- 上线后：固定域名只读回归，再运行有限的专用账号主流程；记录真实部署标识。
- 失败：停止提升部署；必要时关闭技能或恢复上一部署，不删除或回滚教师草稿来掩盖问题。
- 定时巡检可后续接入CI或合成监控。本轮不自动创建定时任务或购买服务。

## 新功能取舍

### 优先：只重试保存，不重新生成

教师得到满意回答后，不应因保存失败再付一次生成费用。就地保存已生成的同一份结果；明确显示保存中、保存成功、冲突或需登录。当前页面保留可验证的待保存payload；刷新后不能安全恢复写入意图时，先导出而不是盲写。

### 下一步候选：教学条件变更预览

从一课时改两课时前，明确显示哪些课堂环节将调整、哪些教师锁定内容保持不变。教师确认后再生成，减少“点了按钮不知道改了什么”。先做同一草稿内的差异预览，不新增导航入口。

### 下一步候选：课前可用性检查

进入课堂前检查三卡是否保存、必要卡片是否锁定、是否仍有待核对引用，并提供直接修复入口。只报告可验证状态，不给虚假的教学质量分数；不重复已有课堂入口。

## 本轮已实现的产品切片

“仅重试保存”已在开发分支实现：仅对已有草稿按原版本重试PATCH；绑定原账号、篇目和已生成payload，不调用模型。保存期间阻止再次保存及追问，失败保留结果；409冲突、锁定或身份失效后移除重试入口，保留导出。

新建草稿POST一旦尝试过，不再提供盲重试：断网或500不保证服务器没创建成功，缺少幂等键时再次POST可能重复建草稿。此场景先保留回答与导出，后续应独立实现服务端幂等创建再扩大恢复能力。

待保存payload只在当前页面内存中；刷新/重新登录不会从展示文字重建写请求。恢复操作区增加换行与44px按钮高度，纳入390px窄屏测试。此功能尚未部署到生产，以上5项线上结果不作为新功能上线证据。

最终开发验证：692/692单测通过，`npm run check`（含构建）通过，13/13相关浏览器用例通过（48.6秒），其中保存重试路径在390px视口验证无横向溢出；复用上一批66项完整回归，不将本次13项误报为全站每个按钮均已点击。
