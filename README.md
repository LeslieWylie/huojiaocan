# 活教参

活教参是一套面向初中语文教师的循证备课与课堂工作台。它把课程标准、学生教材和教师教学用书放在同一条可核验链路中，支持教师从篇目定位开始，连续追问、确认方案、生成一课三卡，并把课堂记录接续到复盘与下一课。

生产入口：<https://app.huojiaocan.workers.dev/>

## 核心流程

```text
选择篇目
  → 核对学生教材与教师教学用书
  → 围绕当前篇目连续追问
  → 教师确认备课方案
  → 生成并编辑板书卡、提问卡、评价卡
  → 保存、锁定、投影或导出
  → 记录课堂事实并进入课后复盘
```

关键原则：

- **教材为主**：模型只能组织服务端提供的教材依据，不能自行生成页码、文档身份或核验链接。
- **篇目身份稳定**：追问“换成两课时”等调整指令只改变教学安排，不改写篇目和板书课题。
- **教师最终确认**：AI 初稿可继续追问和编辑；只有教师确认后才能生成正式三卡。
- **结果可接续**：草稿、版本、锁定卡片、课堂记录和班级接续均以账号数据为准。

## 当前能力

- 三源材料：课程标准、学生教材、教师教学用书。
- 教材目录、跨教材搜索、物理页定位和原页核验。
- 带完整近期问答上下文的连续备课，以及“Pi Agent 目录选节与原页阅读—按需补搜—结构化初稿—教材审校—定向修订”的有限轮次工作流。
- 方案定稿、版本恢复、一课三卡、渐进式板书、课堂投影与导出。
- 教研资产、同课异构、听评课、问题链预演、课前摸底、分层作业和课后复盘。
- Supabase 邮箱密码登录、账号隔离和个人 DeepSeek 连接管理。

## 技术结构

```text
React/Vite 教师端
  └─ 同源 BFF API
      ├─ Supabase Auth / Postgres / Storage
      ├─ 自部署 PageIndex 教材索引
      ├─ pi-agent-core 检索工具循环
      ├─ 系统 OpenAI 兼容模型网关
      └─ 用户个人 DeepSeek 官方接口（可选）
```

### Agent 工作方式

服务端把一次教师请求拆成四个有边界的阶段，而不是让模型一次性自由生成：

1. **依据定位**：识别本轮是首次备课、连续追问、方案调整还是三卡生成；备课类任务先检查学生教材、教师用书以及当前范围内的课程标准是否齐全。
2. **方案初稿**：模型只读取服务端整理的篇目身份、备课条件、近期对话和教材片段；不能提供文档编号、页码或引用链接。
3. **教材与课堂校核**：用确定性规则检查课时覆盖、活动顺序、时间分配、三卡结构和引用编号；必要时只修订不合格部分。
4. **教师确认**：系统输出始终停在“待教师核对”，确认、锁定和课堂使用属于教师操作。

`demo/serverless/teaching-agent-contract.js` 定义回合类型、所需材料、依据门和安全状态事件；`pi-retrieval-agent.js` 编排目录选节、原页阅读与补充搜索；`pageindex-reading-context.js` 将已授权教材中的真实目录节点映射为本轮临时句柄，模型不能自填文档或页码；`grounded-answer.js` 负责结构化生成与校核。三者都不拥有教材页码，物理页和引用身份仍由索引服务与服务端快照校正后绑定。

检索阶段最多补搜2次、读取2次（最多4个原页），受共享截止时间约束。整页替换同页摘要，保留不同材料的上下文位置；超时保留已核验材料，不自动重建索引。生成阶段最多3轮，审校发现的问题必须传入定向修订；未消除的问题保留为待教师判断，不把模型审校视为正确性保证。

目录定位、节点阅读的分工参考 [PageIndex Tree Search](https://docs.pageindex.ai/tutorials/tree-search)。现有自部署服务的 `/retrieve` 仍包含词面相关性召回；本轮是在其目录/原页接口之上补齐 Pi 的推理式选节阅读，不宣称替换了底层召回算法或接入官方托管服务。

Agent 的 turn / grounding / host-event 分层参考了 Anthropic 的 [commerce-agents](https://github.com/anthropics/commerce-agents)（Apache-2.0）；项目只移植机制，不引入其零售领域代码或 Python 运行时。

目录说明：

- `demo/`：教师端、BFF、领域模块和测试。
- `services/pageindex-service/`：自部署 PageIndex 适配服务。
- `supabase/`：数据表、RLS 与迁移。
- `deployment/`：Cloudflare Worker 等部署配置。
- `docs/`：架构、交付、验收和比赛材料。

## 协作约定

- 页面逻辑放在 `demo/src/views/`；`App.jsx` 只保留路由装配。
- 共享领域逻辑优先放入 `demo/shared/`，不要把服务端规则复制到组件中。
- 教师端不展示内部服务名、错误码和部署细节；开发者文档可以保留技术名称。
- 新页面必须加入 `ROUTES`、Vite 构建入口和导航合同测试。
- 新按钮必须有明确动作和可读名称；新链接必须指向已声明页面。`npm run check` 会校验按钮、链接与路由合同。
- 教材定位必须同时保持文档、物理页、篇目、目录节点和返回地址一致。
- 不提交密钥、账号密码、服务端环境值、真实教材原文或本地运行产物。

## 验证方式与边界

```bash
cd demo
npm test                         # 领域和接口测试
npm run check                    # 引用、按钮/路由、架构图检查及生产构建
npm run test:e2e                  # 本地浏览器流程，使用模拟账号/模型服务
npm run test:smoke:production     # 公网只读浏览与搜索
```

本地 E2E 能验证页面、请求、保存与恢复流程，但模拟模型输出不代表真实教学质量；公网只读测试不代表登录后付费模型链路已验收。31 页检查验证渲染、布局、控件名称和链接目标，不等于逐一点击所有业务操作。真实账号的生成质量、教材原页内容与引用匹配仍需要专项回归。

### 会话持久化与账号边界

- 模型API不承担会话存储。问答以账号所属草稿为上下文真源，服务端只读取当前JWT用户的历史；客户端传来的历史不再补入模型上下文。
- 登录刷新合并并发请求，在支持Web Locks的浏览器中跨标签页串行刷新；临时断网保留登录，失效凭据才清除。退出/切换账号后，旧请求不能覆盖新会话或用新账号重试。
- 浏览器只按账号保存当前连接的`keyId`选择，包括明确选择系统连接；不保存DeepSeek原始密钥。关闭浏览器后的选择恢复与服务端草稿恢复是两套独立机制。
- 新增本地`account-persistence.spec.cjs`覆盖退出、B账号拒绝A草稿、A重登恢复以及跨标签页退出；`index-isolation.test.js`覆盖服务端owner过滤、密钥操作和Pi请求隔离。外部传输为mock，不能替代生产RLS验证。
- 已生成但尚未保存成功的本地内容，不会冒充已归属服务端草稿的历史传给模型；应先恢复保存，再继续追问。
